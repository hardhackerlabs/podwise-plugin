# Podwise

Podwise skills help you get more out of every podcast you listen to. All capabilities are reached through the **Podwise MCP server** — there is no CLI to install.

## References

Load these files when needed — do not load all of them upfront:

- [references/mcp.md](references/mcp.md) — full MCP tool reference. Load before calling any Podwise tool or looking up parameters.
- [references/installation.md](references/installation.md) — MCP connection and OAuth setup. Load if the Podwise MCP tools are unavailable or unauthenticated.
- `taste.md` in the current working directory — the user's listener profile, generated by the `refine-taste` workflow. Load at the start of any workflow that benefits from personalisation. Not present until the user has run `refine-taste`.

## Environment Check

Before running any workflow, verify the Podwise MCP server is connected by calling:

- `get_me` — returns the account email, plan, and remaining AI processing credits.

If the Podwise tools are not available or `get_me` fails with an authentication error, load [references/installation.md](references/installation.md) and stop until the connection is set up.

> Tool names may be prefixed by the host with the server name (for example `podwise_get_me`). Use whatever prefix the host exposes.

## Tool Reference

Before calling a Podwise tool, load [references/mcp.md](references/mcp.md) as the source of truth for exact tool names, parameters, return shapes, and quota rules. Do not guess tool signatures from memory.

## Identifier Rules

Every tool identifies content by numeric IDs, not URLs:

- Episode: `episodeSeq` from `https://app.podwise.ai/dashboard/episodes/<seq>`
- Podcast: `podcastSeq` from `https://app.podwise.ai/dashboard/podcasts/<seq>`

When the user pastes a Podwise URL, extract the trailing integer and pass it as the seq. Link episodes back as `https://app.podwise.ai/dashboard/episodes/<seq>`.

## First-Time Setup

If the taste profile does not exist yet, suggest running the `refine-taste` workflow before any other workflow. Other workflows will still run without it, but their outputs will not be personalised.

Once you identify the right workflow, load that file and follow its instructions exactly.

If the user's intent matches more than one workflow, ask one clarifying question before routing. If it matches none, ask what they are trying to accomplish. Do not guess.

Some requests can be handled directly with a single MCP tool call without loading a workflow. Load [references/mcp.md](references/mcp.md) and execute directly when the user's intent is a single, self-contained operation:

- Follow or unfollow a podcast — `set_podcast_follow`
- Search for an episode or podcast by name — `search_episodes` / `search_podcasts`
- Check what's trending — `get_popular_episodes`
- Browse listening or reading history — `list_my_episodes`
- Fetch a specific artifact from an episode — `get_episode_summary` / `get_episode_transcript`
- Ask a one-off question from transcripts — `ask_podwise`
